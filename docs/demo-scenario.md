# Сценарій демонстрації (8–10 хвилин)

Демонстрація проходить без презентації: IntelliJ IDEA, Tomcat, JavaFX, phpMyAdmin, Terminal, GitHub.

## Підготовка (до захисту)
1. XAMPP: запущено MySQL. У phpMyAdmin виконано `database.sql` (свіжа база).
2. Початкові ідентифікатори після свіжого `database.sql`: особи 1–4, події 1–2, завдання 1–7, ресурси 1–5.
   Перевірка: `SELECT id, title, status, priority_index FROM tasks;`
3. `cd server && mvn clean test && mvn clean package` — зафіксувати кількість тестів і BUILD SUCCESS.
4. WAR скопійовано в `webapps` Tomcat 9.x, Tomcat запущено; у браузері відкривається `/event-manager-server/tasks`.
5. Клієнт: `cd client && mvn javafx:run`.
6. Тимчасові записи для CRUD (створюються й видаляються під час показу): ресурс «Демо-ресурс», завдання «Демо-завдання».

## Контрольні значення показника I
Показник залежить від поточного часу (F1), тому на демонстрації порівнюється формула. Контрольні значення, відтворювані
в тестах із фіксованим часом: F1=80 (дедлайн через 6 діб), F2=80 (критичність 4), F3=0 → **I = 60**;
після додавання однієї залежної задачі F3=20 → **I = 65**; критичність 5 → F2=100 → **I = 67**;
F1=80, F2=80, F3=40 → **I = 70**. Для завдання зі стану ВИКОНАНО показник не відображається («—»).
На демонстрації: створити завдання з дедлайном «зараз + 6 діб» і критичністю 4 → I ≈ 60 (трохи менше через хвилини, що минули).

## Хід показу
| Хв | Дія | Що показати |
|----|-----|-------------|
| 0–1 | Структура проєкту в IDEA, GitHub-репозиторій (README, історія commit-ів, tag `coursework-final`) | `server`, `client`, `database.sql`, `sample-data` |
| 1–2 | Браузер: GET `/tasks`, `/persons` | JSON-відповіді сервера; `logs/server.log` |
| 2–4 | JavaFX: вкладки; CRUD ресурсу (додати, змінити, видалити) | після кожної дії — `SELECT` у phpMyAdmin |
| 4–5 | Перевірка пов'язаних записів | подія з неіснуючим організатором, завдання з порожньою назвою — повідомлення про помилку |
| 5–7 | Життєвий цикл: СТВОРЕНО → ПРИЗНАЧЕНО → ВИКОНУЄТЬСЯ → ВИКОНАНО | заборонений перехід (СТВОРЕНО → ВИКОНАНО) відхиляється; показник I; залежність підвищує I передумови |
| 7–9 | CSV: «Імпортувати CSV» (завдання) | ProgressBar і текст ходу; вікно підсумку; таблиця оновилась; дані в MySQL; повторний імпорт — усі рядки відхилено як дублікати |
| 9–10 | Негативні сценарії та тести | `tasks_with_errors.csv`; зупинити Tomcat → імпорт/оновлення показує «Сервер недоступний»; результат `mvn clean test` |
